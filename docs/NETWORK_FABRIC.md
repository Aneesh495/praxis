## 1. WireGuard Full-Mesh Cryptographic Peering

Praxis generates complete, declarative WireGuard mesh configurations (`wg0.conf`) across all nodes defined in a cluster topology:

```ini
# Auto-generated by Praxis Network Fabric
[Interface]
PrivateKey = <sealed-secret-ref>
Address = 10.100.1.5/24
ListenPort = 51820
FwMark = 0x5182

[Peer]
# Peer: cluster-node-02 (eu-central-1)
PublicKey = fGz...7Kq=
PresharedKey = <sealed-psk-ref>
Endpoint = 198.51.100.22:51820
AllowedIPs = 10.100.1.6/32, 10.200.0.0/16
PersistentKeepalive = 25
```

### 1.1 Cryptographic Properties
- **Noise Protocol Framework**: Implements `Noise_IKpsk2`:
  - 1-RTT mutual authentication with ephemeral Curve25519 Diffie-Hellman key exchange.
  - Symmetric session keys rotated every several minutes or after 1 GiB of data transfer.
  - Pre-shared symmetric keys (PSK) provide quantum resistance against future harvest-now-decrypt-later attacks.
- **Identity-Driven Routing (Cryptokey Routing)**: Traffic is associated strictly with the sender's public key. Spoofed source IP packets are rejected immediately in kernel space before reaching the networking stack.

## 2. Automated eBPF XDP Packet Filter Synthesis

To defend microVM instances against high-volume network floods and enforce strict perimeter isolation, Praxis translates high-level firewall policies directly into eBPF C kernels executing at the network interface card (NIC) driver level.

### 2.1 Declarative Policy Specification
```nix
network.firewall.rules = [
  {
    protocol = "tcp";
    destinationPort = 443;
    action = "accept";
    description = "Permit ingress HTTPS traffic";
  }
  {
    protocol = "udp";
    destinationPort = 51820;
    action = "accept";
    description = "Permit WireGuard encrypted overlay packets";
  }
  {
    action = "drop";
    description = "Default-deny policy for all other ingress traffic";
  }
];
```

### 2.2 Synthesized eBPF Kernel (C Code)
The Praxis generator produces strict, bounds-checked eBPF C source:

```c
// Synthesized by Praxis Engine eBPF Generator
#include <linux/bpf.h>
#include <linux/if_ether.h>
#include <linux/ip.h>
#include <linux/tcp.h>
#include <linux/udp.h>
#include <bpf/bpf_helpers.h>

SEC("xdp")
int xdp_filter_ingress(struct xdp_md *ctx) {
    void *data_end = (void *)(long)ctx->data_end;
    void *data = (void *)(long)ctx->data;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > data_end)
        return XDP_DROP;

    if (eth->h_proto != __constant_htons(ETH_P_IP))
        return XDP_PASS;

    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > data_end)
        return XDP_DROP;

    if (ip->protocol == IPPROTO_TCP) {
        struct tcphdr *tcp = (void *)(ip + 1);
        if ((void *)(tcp + 1) > data_end)
            return XDP_DROP;

        if (tcp->dest == __constant_htons(443))
            return XDP_PASS;
    } else if (ip->protocol == IPPROTO_UDP) {
        struct udphdr *udp = (void *)(ip + 1);
        if ((void *)(udp + 1) > data_end)
            return XDP_DROP;

        if (udp->dest == __constant_htons(51820))
            return XDP_PASS;
    }

    return XDP_DROP; // Default deny
}

char _license[] SEC("license") = "Dual MIT/GPL";
```

Executing at the XDP driver hook bypasses the Linux SKB (socket buffer) allocation layer entirely, enabling line-rate packet filtering at tens of millions of packets per second per core.

## 3. Mutual TLS (mTLS) Public Key Infrastructure

Praxis generates a complete, hierarchical X.509 PKI tree:

```
[ Root Certificate Authority (Offline Key, ed25519) ]
                         |
                         v
[ Regional Intermediate CA (us-east, eu-central) ]
                         |
           +-------------+-------------+
           |                           |
           v                           v
[ Node Identity Cert ]      [ Workload Service Cert ]
(SAN: DNS, IP, SPIFFE ID)   (SAN: microvm.praxis.internal)
```

- **Cryptographic Algorithms**: Ed25519 signatures with SHA-512 digests for high speed and side-channel immunity.
- **SPIFFE Identifiers**: Workload certificates embed SPIFFE IDs (`spiffe://praxis.local/ns/workloads/sa/worker-01`) within standard Subject Alternative Name (SAN) extensions, providing verifiable zero-trust identity between microVM guest services.
- **Automated Revocation**: Supports CRL and OCSP stapling configurations for real-time certificate invalidation.
